# Product implementation roadmap

I would divide the product into **12 major phases / ~30 implementation sprints**.

The important distinction:

* **Phase 0–7 → Launchable commercial MVP**
* **Phase 8–10 → Scale/product maturity**
* **Phase 11 → post-MVP expansion**

## Sprint 2.4 — Event ingestion

Create an internal ingestion layer:

```text

      ↓

      ↓

```

### Critical design decision

Don't immediately run the entire AI pipeline inside the webhook request.

The webhook should:

```text
receive
validate
persist
ack
```

Then processing happens asynchronously.

This protects us from Meta/network/LLM latency.

# How we'll use AI coding agents

This is particularly important.

I don't want us giving the agent:

> "Build the entire AI lead nurturing platform."

That's how projects become inconsistent.

Instead, every sprint will have:

```text
SPRINT
│
├── Objective
├── Existing-state inspection
├── Scope
├── Files/modules allowed
├── Data model
├── API contract
├── Business rules
├── Edge cases
├── Security requirements
├── Tests
├── Build verification
└── Stop condition
```

And the agent instruction will be:

```text
Inspect first.
Reuse existing code.
Implement only this sprint.
Do not redesign unrelated modules.
Do not implement future phases.
Run required verification.
Report only what was actually changed/verified.
Stop.
```

That fits the way you've been using OpenCode/Aloha/Ox and keeps the agents from expanding scope.
